## Coppice Noir：第二个主题预设 + 深色骨架

**起因**：刘工问"shopify 可以配置预设主题，好像叫 schema-color 对吗"——**两个名字揉一起了**。

- **theme preset**（编辑器里叫 Theme style）→ `config/settings_data.json` 的 `presets`，商家在「主题设置 → 主题风格」一键换整套；
- **`color_scheme`** → `settings_schema.json` 里的一种设置类型，给**单个 section** 挑配色；本主题未采用该体系。
- 关系是**嵌套**：preset 是整套快照，`color_schemes` 是快照里的一格（Dawn 的 settings_data.json 正是此结构，5 套 scheme 全在 `presets.Dawn` 内）。另有 `color_palette`（把色值打包成一组设置），本主题无关。
- **平台硬约束（已核实官方原文）**：一个 preset = Theme Store 上一个**独立 listing + 一个独立演示店**；多 preset 时提交包必须带 `/listings/<preset-name>/`。所以加第二 preset 会直接推翻 v1.0 的"单 preset、不需要 /listings"——SDD §12 把 `Coppice Pro` 排在 v1.1 正是这个原因。
- **刘工拍板**：① 要作为第二 listing；② 深色**只覆盖骨架**（页头组 + 页脚），内容区保持浅色。

### 落地形态（本轮最重要的架构决策）

颜色体系原本是**扁平 4 个全局色**（background / foreground / brand / brand-accent），没有 color_scheme 体系。深色骨架**没有**去改那 50 余处 `var(--color-*)` 引用，而是：

1. `settings_schema.json` 的 Colors 组加 3 个**可清空**的 color 设置（`skeleton_background_color` / `skeleton_foreground_color` / `skeleton_accent_color`），**故意不写 default** —— 清空返回 blank，靠 `| default: settings.xxx` 回落全局色，商家因此能表达"跟随全局"；
2. `snippets/css-variables.liquid` 输出 `--color-skeleton-*`；
3. `assets/critical.css` 加**一条变量重映射**规则：`site-header, .site-footer { --color-background: var(--color-skeleton-background); … }`。

**为什么能这么省**：CSS 变量是继承的，重映射后骨架内所有 `var(--color-*)` 自动翻转——包括 mega 面板与两个用 `showModal()` 打开的 `<dialog>` 抽屉（top layer 只改层叠顺序、不改 DOM 继承链）。更关键的是，作者当初把导航/mega 的"浅色叠加"写成 `color-mix(in srgb, var(--color-foreground) N%, transparent)`，前景色一翻转、叠加方向自动跟着翻，那 50 余处引用**一行没动**。

**浅色预设零回归的保证**：三色留空时等于全局色 → 重映射规则不产生任何视觉变化。故 `Coppice` preset 的骨架三色留空 —— [**同日补记更正：留空必须显式写 `""` 才可靠，原因见文末 BUG-038**]，`Coppice Noir` 带 `#0F1012 / #E9E9EC / #A3E635`。

**附带改动**：`sections/footer.liquid` 根元素加 `class="site-footer full-width"`，并补 `padding-inline: calc((100% - var(--content-width)) / 2)`（**不能用 `--page-margin`**——宽屏时内容列被 `--page-width` 收窄，直接补页边距会失准）+ `flex-wrap: wrap`（加内边距后小屏不再溢出）。**这是浅色下唯一可见的变化**（页脚多出 1.5rem 上下留白）。

**Noir 色值理由**（对比度按 WCAG 算过）：背景不用 `#000`——OLED 上卡片边界会"融化"、滚动还闪；文字不用纯白——在近黑上有光晕（halation）。品牌色 `#1E4B3C` 在 `#0F1012` 上只有 **1.93:1**，必须提亮成 `#A3E635`（→ **12.6:1**）。公告栏本来就是「brand 底 + background 色字」的写法，所以亮绿底配近黑字**自动成立**（12.6:1）。

**修正一处先前的判断**：我起初说 `sections/hero-slideshow.liquid` 的 CTA 硬编码 `color: #ffffff` 必须改。在"浅色内容区"这个前提下**不成立**——内容区 brand-accent 仍是深绿 `#2E6B4E`，白字对比度安全。**最终未改该文件**。

## 补记（同日第二轮）：本地切换预设的机制核实 + 三处更正

**起因**：刘工问"本地怎么切换主题颜色预设"。

### 1. `shopify theme check` 本地可跑 —— 更正长期错误认知

`which shopify` → `/Users/mac/.nvm/versions/node/v24.22.0/bin/shopify`。它是**纯静态检查，不联网、不需登录**，实测：

- 全量跑：**53 文件 0 offenses**；
- 为确认它到底检不检 `config/`，人为往 `config/settings_data.json` 注入语法错误 → 立刻报 `[error]: ValidJSON` 并**点名该文件**，随后已恢复。

⇒ 两处更正：① `.workbuddy/memory/MEMORY.md` 里"沙箱内 CLI 不可见"**不成立**，已改写；② 本文件上文的"theme check 待刘工代跑"已划掉。`dev-docs/` 下历年积压的一批同类待办（`task-header.md`、`task-collection.md`、`acceptance-checklist.md` 等多处）**Agent 可自行清理**，待刘工确认后批量跑。

**附带结论**：既然 `ValidJSON` 确实查 `settings_data.json`，而带 `/* */` 注释的版本 0 offenses ⇒ **该文件里的块注释（任意位置）与尾随逗号是被官方工具链认可的**（官方 JSONSyntaxError 的 Pass 示例本身就带尾随逗号）。这解决了我先前"注释能否放对象内部"的疑虑，可以放心在 settings_data.json 里写说明性注释。

### 2. preset 切换的覆盖语义（官方原文，直接决定 BUG-038）

官方 settings-data-json 文档原文：*Selecting a theme preset updates the `current` object to use the associated theme preset values. However, only values from presentational settings are updated.*

- 覆盖范围 = presentational 类型：checkbox / color / color_background / color_palette / color_scheme / color_scheme_group / font_picker / number / radio / range / select。**本主题 13 个设置全部落在此列**。
- 语义是"**把 preset 的值更新进 current**"，**不是整体替换** ⇒ preset 里缺席的键会沿用 current 里的旧值 ⇒ 这就是 BUG-038 的根因。
- `content_for_index` / `blocks` 不受影响 ⇒ **judge.me app embed 不会被 preset 切换清掉**。上文待办里那条"切换是否重置 app embed"的风险，**据官方语义可判定为安全**（仍建议开发店顺带确认）。
- 一个主题**最多 5 个 preset**（settings_data.json 上限 1.5MB）。

### 3. color 清空的官方语义

官方原文：*If default is omitted, merchants see a Clear option in the editor. Clearing stores `""` in settings_data.json and returns blank in Liquid.*

⇒ 印证本主题"三项不写 default + `| default:` 回落"的设计正确。另发现 color 类型支持 `placeholder` 属性（*A placeholder value shown in the picker when no color is set*），已给三项补 `"placeholder": "Inherited"`，编辑器里的空色块不再是一片空白。

### 5. 本地切换的三条路（答复刘工）

1. **纯本地**：`python3 tools/use-preset.py "Coppice Noir"` —— 直接改 `current`，不联网、不开编辑器；`--list` 看当前激活项。
2. **`shopify theme dev --theme-editor-sync`** —— 双向同步，编辑器里切风格会写回本地文件。注意 `-e` 是 `--environment`（对应 `shopify.theme.toml` 的 `[environments.coppice]`），**不是**它的短名。
3. **`shopify theme dev`（默认单向）＋ 编辑器切 ＋ `shopify theme pull --only config/settings_data.json`** —— 默认**不会**自动回流到本地，这是最容易踩的坑。

**验收**：theme check 53 文件 0 offenses（Noir / Coppice 双向切换后各复跑一次）；`use-preset.py` 往返切换正确、`--list` 正确识别当前激活项。
