## Coppice Noir：第二个主题预设 + 深色骨架

**起因**：刘工问"shopify 可以配置预设主题，好像叫 schema-color 对吗"——**两个名字揉一起了**。

- **theme preset**（编辑器里叫 Theme style）→ `config/settings_data.json` 的 `presets`，商家在「主题设置 → 主题风格」一键换整套；
- **`color_scheme`** → `settings_schema.json` 里的一种设置类型，给**单个 section** 挑配色；本主题未采用该体系。
- 关系是**嵌套**：preset 是整套快照，`color_schemes` 是快照里的一格（Dawn 的 settings_data.json 正是此结构，5 套 scheme 全在 `presets.Dawn` 内）。另有 `color_palette`（把色值打包成一组设置），本主题无关。
- **平台硬约束（已核实官方原文）**：一个 preset = Theme Store 上一个**独立 listing + 一个独立演示店**；多 preset 时提交包必须带 `/listings/<preset-name>/`。所以加第二 preset 会直接推翻 v1.0 的"单 preset、不需要 /listings"——SDD §12 把 `Coppice Pro` 排在 v1.1 正是这个原因。
- **刘工拍板**：① 要作为第二 listing；② 深色**只覆盖骨架**（页头组 + 页脚），内容区保持浅色。

### 落地形态（本轮最重要的架构决策）

颜色体系原本是**扁平 4 个全局色**（background / foreground / brand / brand-accent），没有 color_scheme 体系。深色骨架**没有**去改那 50 余处 `var(--color-*)` 引用，而是：

1. `settings_schema.json` 的 Colors 组加 3 个**可清空**的 color 设置（`skeleton_background_color` / `skeleton_foreground_color` / `skeleton_accent_color`），**故意不写 default** —— 清空返回 blank，靠 `| default: settings.xxx` 回落全局色，商家因此能表达"跟随全局"；
2. `snippets/css-variables.liquid` 输出 `--color-skeleton-*`；
3. `assets/critical.css` 加**一条变量重映射**规则：`site-header, .site-footer { --color-background: var(--color-skeleton-background); … }`。

**为什么能这么省**：CSS 变量是继承的，重映射后骨架内所有 `var(--color-*)` 自动翻转——包括 mega 面板与两个用 `showModal()` 打开的 `<dialog>` 抽屉（top layer 只改层叠顺序、不改 DOM 继承链）。更关键的是，作者当初把导航/mega 的"浅色叠加"写成 `color-mix(in srgb, var(--color-foreground) N%, transparent)`，前景色一翻转、叠加方向自动跟着翻，那 50 余处引用**一行没动**。

**浅色预设零回归的保证**：三色留空时等于全局色 → 重映射规则不产生任何视觉变化。故 `Coppice` preset 的骨架三色留空 —— [**同日补记更正：留空必须显式写 `""` 才可靠，原因见文末 BUG-038**]，`Coppice Noir` 带 `#0F1012 / #E9E9EC / #A3E635`。

**附带改动**：`sections/footer.liquid` 根元素加 `class="site-footer full-width"`，并补 `padding-inline: calc((100% - var(--content-width)) / 2)`（**不能用 `--page-margin`**——宽屏时内容列被 `--page-width` 收窄，直接补页边距会失准）+ `flex-wrap: wrap`（加内边距后小屏不再溢出）。**这是浅色下唯一可见的变化**（页脚多出 1.5rem 上下留白）。

**Noir 色值理由**（对比度按 WCAG 算过）：背景不用 `#000`——OLED 上卡片边界会"融化"、滚动还闪；文字不用纯白——在近黑上有光晕（halation）。品牌色 `#1E4B3C` 在 `#0F1012` 上只有 **1.93:1**，必须提亮成 `#A3E635`（→ **12.6:1**）。公告栏本来就是「brand 底 + background 色字」的写法，所以亮绿底配近黑字**自动成立**（12.6:1）。

**修正一处先前的判断**：我起初说 `sections/hero-slideshow.liquid` 的 CTA 硬编码 `color: #ffffff` 必须改。在"浅色内容区"这个前提下**不成立**——内容区 brand-accent 仍是深绿 `#2E6B4E`，白字对比度安全。**最终未改该文件**。

### 2. preset 切换的覆盖语义（官方原文，直接决定 BUG-038）

官方 settings-data-json 文档原文：*Selecting a theme preset updates the `current` object to use the associated theme preset values. However, only values from presentational settings are updated.*

- 覆盖范围 = presentational 类型：checkbox / color / color_background / color_palette / color_scheme / color_scheme_group / font_picker / number / radio / range / select。**本主题 13 个设置全部落在此列**。
- 语义是"**把 preset 的值更新进 current**"，**不是整体替换** ⇒ preset 里缺席的键会沿用 current 里的旧值 ⇒ 这就是 BUG-038 的根因。
- `content_for_index` / `blocks` 不受影响 ⇒ **judge.me app embed 不会被 preset 切换清掉**。上文待办里那条"切换是否重置 app embed"的风险，**据官方语义可判定为安全**（仍建议开发店顺带确认）。
- 一个主题**最多 5 个 preset**（settings_data.json 上限 1.5MB）。

### 3. color 清空的官方语义

官方原文：*If default is omitted, merchants see a Clear option in the editor. Clearing stores `""` in settings_data.json and returns blank in Liquid.*

⇒ 印证本主题"三项不写 default + `| default:` 回落"的设计正确。另发现 color 类型支持 `placeholder` 属性（*A placeholder value shown in the picker when no color is set*），已给三项补 `"placeholder": "Inherited"`，编辑器里的空色块不再是一片空白。

1. **纯本地**：`python3 tools/use-preset.py "Coppice Noir"` —— 直接改 `current`，不联网、不开编辑器；`--list` 看当前激活项。

## 补记二（同日第三轮）：Sort by 移到商品列表右上方（效果图-集合-1）

**起因**：刘工指 `Sort by` 应放商品列表右上方（与商品数同行靠右），并给了效果图 `dev-docs/local-assets/效果图-集合-1.png`。原实现放在左列筛选面板顶部（注释自认"Dawn 同款"）。

### 结构约束与解法

- **不能把 `<form>` 扩大到工具条**：商品网格里有 quick-add 的嵌套表单，HTML 不允许表单嵌套。
- **解法：`form` 属性关联**——`<select name="sort_by" form="FacetsForm-{{ section.id }}">` 留在右列工具条，逻辑上仍是筛选表单成员：`FormData(form)` 会包含 form 属性关联的控件，无 JS 时点「应用」按钮照样带上 `sort_by`。
- **工具条 DOM 顺序**改为 open 按钮（移动端）→ 商品数 → 排序 → 已选标签（`flex-basis:100%` 独占第二行），对应效果图两行结构。
- **无筛选集合**：原 form 里只有 sort，移走后 form 变空壳、左列 230px 全空——改为 `filters.size == 0` 时不渲染 form + `.collection__layout--no-facets` 单列；JS 侧 sort change 走独立局部更新（`_load` + 回第一页）。

### 顺带修掉一个既有 bug（BUG-039）

`_onChange` 用的 `this._form` 是 `connectedCallback` 缓存的引用，而 `_load` 的 `replaceChildren` 会替换整个容器——**首次筛选后缓存即脱离 DOM，第二次变更筛选请求发不出去**（JS 就绪后 Apply 按钮隐藏，change 是唯一提交入口，等于必踩）。修复：`_onChange` 现场重查 form；删除 `_form` 实例字段。教训进 bugs.md：**委托监听组件里实例字段缓存的 DOM 引用不能跨容器替换存活**。

### 排查工具注意

macOS 自带 BSD grep 默认 BRE，`\|` 不是"或"——本轮两次 grep 空结果均由此误判（一度以为集合页没有排序）。**一律用 `grep -E`**。

**验收**：theme check 53 文件 0 offenses；locale keys ✓；tag balance ✓；node --check ✓。**待开发店实测**：① 排序变更后商品与计数局部刷新、URL 带 sort_by；② **连续两次**筛选/排序都正常（BUG-039 回归点）；③ 移动端抽屉筛选 + 工具条排序并存；④ 无筛选集合不空一列。

## Sort by 工具条返工 + 三个实测缺陷（BUG-040/041/042）

刘工开发店实测反馈三点：① 计数应在 Sort by **右侧**（DOM 顺序换为 sort → count，对应 pages-ui §4「排序 ▾ 共 11 款」）；② 左侧筛选不触发搜索；③ <990px 产品列表被顶到最下方。三个根因全部是**既有缺陷**（`git show HEAD` 核实），非本轮引入：

- **BUG-040（致命，自文件创建起）**：`_buildUrl` 写了 `url.append()`——URL 对象没这方法，应为 `url.searchParams.append`。**筛选提交路径从未走通过**，此前唯一活着的局部更新路径是点击已选标签（不经过 `_buildUrl`）。
- **BUG-041（结构缺陷）**：移动抽屉裸移 `<aside>` 进 `<dialog>`（dialog 挂在 `<collection-facets>` 兄弟位置）→ 控件脱离 form 归属 + 事件不再冒泡到本元素 → **抽屉内勾选不提交、Apply 无效、关闭按钮失灵**（只有 Esc 能关）。修复：**筛选 form 整体移入 dialog**（身份绑定随子树走），同组委托监听同时挂 dialog（submit/change/click/close 五个），局部更新时清旧 form 移新 form，关闭归位 `data-facets-layout` 首位；顺带补点遮罩关闭。
- **BUG-042**：`.facets__aside` 从无流内隐藏规则 → 移动端面板堆在产品上方。修复：`[data-facets-ready] .facets__form { display:none }`（<990px，隐藏 form 整体顺带消掉空 grid 行；无 JS 降级路径不变）。

**核心教训（已进 bugs.md）**：① URL 操作只能走 `searchParams`（`node --check` 查不出运行时 TypeError）；② **物理移动 DOM 前先问"控件身份绑定（form 归属/label/aria）是否随子树走"**——`<form>` 整体移动身份不丢，散件移动必丢；dialog 挂在本元素之外时，本元素的委托监听对其内容全部失效；③ "隐藏组件首次打开可见"必须 DOM 移动逻辑 + 流内隐藏 CSS 两条都落。

**验收**：theme check 53 文件 0 offenses；locale keys ✓；tag balance ✓；node --check ✓。**待开发店实测**：① 桌面勾选筛选→局部刷新、URL 带参数；② 抽屉内勾选→Apply→关闭→再开，状态正确；③ 抽屉关闭按钮与点遮罩关闭生效；④ 移动端产品列表紧跟工具条；⑤ 计数在 Sort by 右侧。

## 抽屉 Apply 从"摆设"改为唯一提交入口（刘工 2026-10-16 问"Apply 还有用吗"，已实现）

刘工发现抽屉内勾选即触发接口，Apply 无实际作用。改为移动端标准模式：

- 验收：node --check ✓、theme check 0 offenses。**待开发店实测**：① 抽屉内勾选不发请求，Apply 一次提交且抽屉收起、结果刷新；② 只发一个请求（无 _onSubmit 双发）；③ 勾选后不 Apply 直接下拉收回 → 重开抽屉勾选状态已回滚、结果未变；④ PC 勾选即刷新不变；⑤ 已选标签在抽屉内仍即时生效。

- 落地：**没有**照搬自定义元素结构——胶囊是服务端渲染的 `<a class="facets__chip">`，转 Shadow DOM 会破坏 `_onClick` 的 `closest('a[href]')` 拦截链。改为：`ChipDissolveFX` 单例引擎（canvas 惰性挂 body，fixed + pointer-events:none）写进 `assets/faceted-filters.js`；`CollectionFacets#_dissolveChip` 在 `_onClick` 拦截到胶囊链接后、`_load` 前 `getBoundingClientRect` 取证并爆发粒子，胶囊本体立即 `opacity:0`（工具条不跳动），新 DOM 替换后自然移除。
- **颜色不硬编码**：色板 = 胶囊文字色（getComputedStyle）→ `--color-brand-accent` 的渐变采样 + 掺两份 `--color-brand`；令牌非法时回落文字色，preset 切换自动跟随。
- reduced-motion 直接跳过（纯装饰不挡功能，与骨架层同一纪律）。
- 验证：`node --check` 通过；`shopify theme check` 53 文件 0 offenses。视觉效果待 `shopify theme dev` 浏览器实测（粒子物理参数移植自参考文件，仅按胶囊小尺寸收窄数量 70–220 / 粒径 ≤2.9px）。

### 粒子消散 v2：风场化 + Clear all 整排碎（刘工追加需求）

- 新参考：`dev-docs/particle- capsule.html`（注意文件名带空格）。物理从"径向爆发+重力"换成**风场**：BASE_WIND{ax:0.11, ay:-0.075, drag:0.99, maxSpeed:11}，初速以右上 -PI*0.3 为基准加扰动，飞出屏幕右上或寿命耗尽移除。
- `distance` 系数（1=默认）同时缩放风场强度/初速/寿命（decayScale=1/max(0.35,d)），近=快散、远=飘久。本项目配置入口：`<collection-facets data-chip-distance="1.2">` 的 data 属性，**不做 section 设置**（纯视觉参数，不值一个 schema 键+两条 locale；要商家可调再升级）。
- Clear all（`.facets__clear`）：`_dissolveAllChips()` 逐颗按各自矩形爆发（换行时位置才准）、色板只采样一次、全部同时碎（刘工点名"一起碎"，无逐颗延迟）。
- 重构：`_chipColors(chip)` / `_hideChip(chip)` 拆为独立方法，单颗与整排共用。
- `node --check` + theme check（53 文件 0 offenses）通过。视觉待 `shopify theme dev` 实测。
