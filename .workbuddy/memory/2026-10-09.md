## BUG-024 修复：{% javascript %} 内不能放 Liquid（theme check 4 offenses）

- 刘工跑 theme check 报 4 offenses，全在 main-nav.liquid：`StaticStylesheetAndJavascriptTags`（JS 块内 Liquid 标签/变量）×2、`JavascriptOncePerFile`、`UnusedAssign`。

- **正确做法（官方给的两条路径）**：

## BUG-024 补充：script_tag filter 不支持 defer，必须手写 <script>

- theme check 复跑后 `ParserBlockingScript`：**`script_tag` filter 即使传 `defer: true` 仍被判为 parser-blocking**。
- **官方明确**（shopify.dev ParserBlockingScript + defer-non-critical-resources 两处）：**script_tag filter 不支持 defer/async 属性，要 defer 就手写 `<script>` 标签**。
- **最终正确写法**：`<script src="{{ 'x.js' | asset_url }}" defer></script>`
  - 执行顺序有依赖 → `defer`；无依赖 → `async`。
  - 与 AGENTS §4 红线无冲突：那条禁的是**压缩版 .js 资源文件**，不是内联引入外部未压缩 JS。
- **已更新 AGENTS.md §6**（上一轮我写的 `script_tag: defer: true` 本身就是错的，已改为手写 script 标签 + 注明 defer/async 选择依据），BUG-024 的修复与预防条款同步补充。
- **教训**：上一轮"查了官方文档就改"仍不够——我查的是 section-assets（讲 javascript 标签机制），没查 ParserBlockingScript 检查项本身。**修 theme check 报错前，要先读那个 check 的官方文档页**，它才说明该检查器认什么、不认什么。同理 BUG-020（箭头）也是规则先于实现。
